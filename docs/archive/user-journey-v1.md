# User Journey V1

## Objectif

Decrire le parcours utilisateur cible de `FitMAS` en V1.

Le produit doit faire ressentir:

- une prise en charge premium
- une personnalisation profonde
- une reduction de la charge mentale
- une proactivite utile, jamais gadget

## Persona cible

Le V1 vise prioritairement:

- des pratiquants endurance motives
- deja engages dans une pratique reguliere
- a l'aise avec un setup initial structure
- sensibles a la personnalisation et aux integrations de donnees

## Promesse percue

L'utilisateur doit ressentir:

`Je n'ai plus a porter seul la planification et les ajustements. Mon equipe FitMAS s'en occupe intelligemment.`

## Parcours global

Le parcours V1 est compose de 6 moments:

1. decouverte et promesse
2. onboarding premium
3. activation initiale du systeme
4. execution quotidienne
5. replanification en cas d'imprevu
6. boucle hebdomadaire de progression

## 1. Decouverte et promesse

Avant meme l'inscription, le produit doit expliquer clairement:

- ce qu'est FitMAS
- ce que fait l'equipe IA
- ce qu'est le double numerique
- pourquoi le setup initial prend du temps
- quelles integrations sont utiles

L'utilisateur doit comprendre que le prix du setup est paye ensuite par une baisse de friction quotidienne.

## 2. Onboarding premium

Objectif:

- construire un double numerique V1 utile
- connecter les donnees critiques
- rendre credible la promesse de personnalisation

Contrainte:

- setup max cible: 20 minutes

### Etape 1: objectifs

L'utilisateur renseigne:

- objectif principal
- eventuelle echeance
- niveau d'ambition
- priorites secondaires

Exemples:

- preparer une course
- mieux recuperer
- augmenter le volume tolerable
- mieux manger pour soutenir l'entrainement

### Etape 2: contexte de vie

L'utilisateur renseigne:

- disponibilites hebdomadaires
- contraintes fixes
- jours preferes
- jours a eviter
- routines existantes

### Etape 3: profil sport

L'utilisateur renseigne:

- historique recent
- niveau perçu
- type de pratique
- tolerance a la charge
- blessures ou fragilites declarees

### Etape 4: profil nutrition

L'utilisateur renseigne:

- preferences alimentaires
- gouts
- aversions
- contraintes alimentaires
- habitudes de repas

### Etape 5: style de coaching

L'utilisateur renseigne:

- ton prefere
- niveau de challenge souhaite
- frequence de relance acceptable
- maniere preferee de recevoir les ajustements

### Etape 6: regles non negociables

L'utilisateur fixe:

- limites personnelles
- habitudes intouchables
- contraintes non contournables

### Etape 7: integrations

L'utilisateur connecte si possible:

- Apple Health / Sante
- Strava
- calendrier
- WhatsApp

### Etape 8: generation du premier plan

Une fois le setup termine:

- l'orchestrateur construit un premier etat du double numerique
- l'equipe genere un plan hebdomadaire initial
- l'utilisateur voit son plan sport + nutrition

## 3. Activation initiale

La premiere experience doit creer la confiance.

L'utilisateur doit voir:

- un plan hebdomadaire lisible
- un plan du jour concret
- des explications simples sur les choix
- les premieres hypotheses du systeme

Le systeme doit montrer qu'il a compris:

- l'objectif
- le niveau
- les contraintes de vie
- les preferences et gouts

## 4. Execution quotidienne

Chaque jour, le systeme suit cette logique:

1. import des donnees
2. reevaluation par l'orchestrateur
3. ajustement si necessaire
4. notification uniquement si utile
5. presentation d'un plan du jour clair

### Ce que l'utilisateur consulte dans l'app

- seance du jour
- objectifs nutrition du jour
- adaptations recentes
- explication simple du pourquoi

### Ce que WhatsApp gere

- check-ins utiles
- demande de clarification en cas de doute
- relance si une adaptation importante est proposee
- recueil ponctuel de feedback apres seance

## 5. Replanification apres imprevu

Le systeme doit briller quand la vraie vie perturbe le plan.

Exemples:

- seance ratee
- fatigue inhabituelle
- agenda modifie
- sommeil degrade
- sortie longue deplacee

Reponse produit attendue:

- l'orchestrateur reevalue
- le plan change sans tout casser
- l'utilisateur comprend rapidement la nouvelle version
- WhatsApp n'intervient que si un arbitrage ou un feedback est necessaire

## 6. Boucle hebdomadaire

Une fois par semaine, le produit doit offrir:

- une vue synthese de la semaine passee
- ce qui a ete suivi ou non
- ce que le systeme a appris
- les ajustements de la semaine suivante

Cette boucle est critique pour faire evoluer le double numerique.

## Premiers signaux de succes

Sous 14 jours, l'utilisateur doit ressentir:

- moins d'effort de planification
- plus de confiance dans le plan
- un sentiment d'etre reellement compris

Sous 30 jours, il doit constater:

- une meilleure adherence
- une meilleure regularite
- un premier sentiment d'optimisation credible

## Moments de magie produit

Les moments differenciants a viser:

- premier plan qui semble deja "juste"
- adaptation automatique apres imprevu
- message WhatsApp qui arrive au bon moment
- sensation que le systeme apprend vraiment de la personne

## Echecs a eviter

Le V1 echoue si:

- le setup semble long sans contrepartie visible
- l'utilisateur a l'impression de nourrir l'outil sans retour fort
- les messages proactifs semblent generiques
- le plan change trop souvent sans rationale claire
- le produit cree plus de charge mentale qu'il n'en retire
